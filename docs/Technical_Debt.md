# Технический долг. Устранение долга

## 1. Анализ технического долга
**Проект:** Мобильное Android-приложение для управления задачами (**Jetpack Compose**) с серверной частью на **Spring Boot** и REST API.

**Признаки технического долга:**
- **Кодовая база Android-приложения:**
  - Дублирование кода при обработке задач (отсутствие выделенного слоя данных - Repository).
  - Логика взаимодействия с сервером реализована прямо в ViewModel.
  - Отсутствие DI (Dependency Injection) для удобного управления зависимостями.
- **Серверная часть:**
  - Контроллеры содержат логику работы с БД, вместо вынесения в сервисный слой.
  - Отсутствие валидации входных данных.
  - Логика обработки ошибок в REST API не стандартизирована.
- **Тестирование:**
  - Отсутствие unit-тестов и интеграционных тестов.
  - Нет автоматизированного тестирования API.
- **Развёртывание:**
  - Отсутствие CI/CD для автоматической сборки и деплоя.

## 2. План мероприятий по устранению технического долга
1. **Рефакторинг мобильного приложения:**
   - Вынести логику взаимодействия с сервером в слой Repository.
   - Внедрить Hilt для Dependency Injection.
   - Улучшить архитектуру, используя MVVM.
2. **Оптимизация серверной части:**
   - Добавить слой `Service` для разделения логики.
   - Внедрить валидацию входных данных через `@Valid`.
   - Унифицировать обработку ошибок (например, через `@ControllerAdvice`).
3. **Добавление тестирования:**
   - Написать unit-тесты для ViewModel в Android-приложении.
   - Интеграционные тесты REST API с использованием JUnit + MockMvc.
   - Автоматизировать тестирование API с помощью Postman/Newman.
4. **Настройка CI/CD:**
   - Добавить GitHub Actions для сборки и тестирования.
   - Внедрить автоматизированное развертывание на сервер.
